# 只读结果由服务端渲染成人话，原始 JSON 退出回复

顾客问「我有哪些订单」，气泡里原来是这样一行：

```
[queryMyOrders] [{"orderNo":"ORD2026101421214197C492","status":"CREATED","totalAmount":5.00,"lines":[…]}]
```

字段名是机器名，状态是裸枚举，金额没有货币符号，前端还得为它单开一条等宽「机器文本」通道。更糟的是**模型那一轮一个字都没写**的时候（实测 `runs.id=35`：53 个补全 token 全花在工具调用上），整条回复就只剩这坨 JSON——顾客问的是订单，收到的是一个数组。

**决策：回复里不再出现原始负载。** 只读工具像变更工具带 `ToolCard` 一样，在 schema 与 handler 旁边声明一个 `ToolReport`（负载 → 给顾客看的 markdown）；`AssistantService` 把**模型的话在前、各渲染块在后**拼成一条回复，负载本身不进 transcript。不变量随之收紧：**只读 ⇒ 有渲染器、无卡片；变更 ⇒ 有卡片、无渲染器**（`ToolSpec` 构造期拒绝其余组合）。渲染块自带引导句（「你名下有 N 张订单：」），所以模型留白的回合照样读得通；空结果是一句「你名下还没有订单。」而不是 `[]`；整整一页时末尾声明「（只列出最近 N 张）」，不把一页当成全部历史。

**这份人话同时就是记忆。** 只读结果内联进 ASSISTANT 消息一直是下一轮「记得」上一轮查到了什么的唯一途径（US-2.1），所以渲染的对象是消息内容本身，不是在它之外再叠一层展示。订单号与金额必须在渲染后仍然在场——这也决定了形态：订单号与 sku 包进行内代码（等宽，可复制），中文标签与 `¥` 金额走正文。原始负载没有消失，它只是退出正文：`ExecutedTool` 同时带着 `rendered` 与 `resultJson`，审计与排障仍能看到机器真相。

**「刚刚那个订单」靠 grounding 修，不靠把结果写进 transcript。** 那一单的订单号在 `pending_actions.result_ref` 里，会话里唯一的痕迹是卡片摘要「Place order: GIZMO-03 × 1」——没有号码。于是 `Grounding` 的定义从「当前可用商品的 sku 与单价」扩宽为「**服务端不得让模型臆造的事实**」，新增一项：本会话最近一次已确认动作的订单号（`findLatestConfirmed`，按客户过滤，跨客户泄露在结构上不可能）。取的是工具自己命名的那个引用，不从负载里刮字段。这与 ADR-0006 是同一条思路，措辞进 `AiPrompts`（ADR-0010）。

**语言。** 系统提示词不再要求「用简洁英文回答」，改为**用顾客使用的语言回答**；并额外要求模型**不要复述工具返回的数据**——列表由服务端渲染，复述就是同一份清单出现两遍。服务端渲染的中文标签固定中文。

考虑过的替代方案：

- **只靠提示词纪律**（「请用可读的中文列出订单」「优先单查而不是全量查」）。放弃：渲染与检索都是**确定性**的活，交给采样就是把它变成概率。实测那次留白正是模型选择只调工具不写正文的结果——提示词拦不住「一个字都没写」。
- **把确认结果写成一条消息**。放弃：卡片已经在渲染同一个结果，写了就是同一张单在一个界面里出现两遍，还要再决定谁让位。改用 grounding 把事实交给模型。
- **加一个「查最近一单」的只读工具**。放弃：ADR-0006 已经否决过同款——把「先搞清楚是哪一单」变成模型的自觉行为，它可以想不起来调用。事实注入是每次调用都在场的。
- **在回复之外给前端加一层「JSON → 可读」渲染**。放弃：那样 transcript 里仍是 JSON，而记忆读的就是 transcript；US-2.1 会要求模型自己解析 JSON，等于把同一件事再做一遍。

代价，说明白：**渲染措辞是中文硬编码**，服务端渲染的那几行不会随顾客语言变成英文（模型自己的话会）；新增只读工具必须提供 `ToolReport`，多一个要写的东西——但它换来的是「加一个工具仍是一次编辑」；grounding 每轮多一次 `pending_actions` 查询（`LIMIT 1`，命中 `(customer_id, status, expires_at)` 索引，可忽略），且 system prompt 因此更不规整、不利于 prompt 缓存；前端机器文本通道删除后，历史消息里**旧格式**的那几行 `[工具名] {JSON}` 会以普通正文呈现，不再有等宽样式（数据无害，只是难看，且随会话归档淡出）。

**后续（[ADR-0016](0016-refuse-illegal-arguments-and-re-ask-once.md)）。** 本则有两处被更新。①呈现形态：「整整一页时末尾声明（只列出最近 N 张）」换成了引导句里说清「共 N 张 / 只列了 K 张，**最近一张是 `ORD-…`**」，订单块也带上下单时间——留白的回合必须由渲染器独自答出「最近一单是哪一单」，不能只声明截断。②上面第三条否决针对的是**新工具**，ADR-0016 没有推翻它：它给现有的 `queryMyOrders` 加了一个 `limit` 参数（能力），并把「模型可以想不起来」这一半交给**确定性兜底 + 有界重问**，而不是交给模型的自觉。本则的按会话收窄不变——「刚刚这个订单」靠 grounding，跨会话的「最近一次下单」归 US-1.9。
