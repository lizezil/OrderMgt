# 后端研发工程师面试作业 — 需求摘录

> 本文档只做一件事：把面试题目中的**需求**逐条摘出来，忠实于原题，不含实现建议。
> 题目原文里的公司介绍、开发方式建议、面试流程与主观评价已剔除（见文末附录）。
> 需求之外的分析（坑位、风险、可选设计）见 [面试作业-需求梳理与坑位分析.md](面试作业-需求梳理与坑位分析.md)，最终设计见 [面试作业-设计定稿.md](面试作业-设计定稿.md)。

## 1. 作业目标

- 搭建一个**结构清晰的 Spring Boot 后端模块**（单体架构演示即可，**不要求**完整微服务集群）。
- 目的：考察**独立完成需求**的能力，以及对 **Spring Boot、AI 集成开发**的熟悉程度。

## 2. 业务背景（与需求相关的部分）

- 业务为**企业级微服务架构**，支撑学习平台、AI 系统及多端 App 的数据交互与业务逻辑。
- 后续重点推进 **AI 与业务系统的深度融合**。
- 对候选人的核心要求：不只写传统业务代码，还要能把 **AI 能力作为一种服务优雅地集成进现有系统**，并处理好 **AI 响应与本地事务 / 数据库操作的一致性与逻辑闭环**。

## 3. 场景（三选一，也可自选）

| 选项 | 场景 |
| --- | --- |
| A | **智能助手集成**：AI 团队已提供"意图识别服务"或"对话接口"，业务服务（如订单管理、客户服务工单系统）根据 AI 识别的意图，自动执行业务代码（创建订单、查询数据库、修改状态等）。 |
| B | **文档摘要与归档**：接收文档内容 → 调用 AI 生成摘要 → 自动提取关键信息并存入数据库。 |
| C | 任意能体现"业务系统 + AI 集成"的场景。 |

> 重点：**不考察 AI 模型训练**，考察的是后端架构与集成。

## 4. 核心考察点（题目明示）

1. **AI 服务调用**：如何封装外部 AI 接口，处理**超时、异常、重试**。
2. **业务逻辑闭环**：AI 返回结果后，如何根据结果**操作本地数据库**。
3. **数据流转**：前端请求 → 业务层 → AI 服务 → 结果解析 → 数据持久化 → 返回前端。

## 5. 必须具备的能力（硬性）

1. **基础 API 接口**：提供 RESTful 接口，供前端或其他服务调用。
2. **AI 工具调用集成**：通过 HTTP Client 或其他方式调用 AI 模型 API，实现 **Function Calling**（让 AI 决定调用哪个业务方法）或直接业务处理。
3. **数据库交互**：使用 JPA / MyBatis 等 ORM 框架，实现数据的持久化与**事务管理**。

## 6. 加分项

1. **架构设计**：代码结构分层清晰，体现"**AI 服务适配层**"与"**业务逻辑层**"的解耦。
2. **工程化实践**：统一异常处理、参数校验、日志记录、API 文档。
3. **流式响应**：AI 回复支持 **SSE**（Server-Sent Events）流式输出。
4. **容器化**：提供 **Dockerfile**，服务可一键 Docker 运行。

## 7. 技术栈（题目推荐，非强制）

| 分类 | 推荐项 |
| --- | --- |
| 核心框架 | Java 17+、Spring Boot 3.x、Spring Cloud |
| 架构模式 | 微服务思想（Service 拆分）、DDD（领域驱动设计） |
| 数据层 | Spring Data JPA / MyBatis-Plus、MySQL / PostgreSQL、Flyway（数据库版本控制） |
| AI 集成 | Spring AI、LangChain4j、或手动封装 HTTP Client（RestTemplate / WebClient） |
| 工具库 | Lombok、MapStruct、Hutool |
| 测试 | JUnit 5、Mockito、Spring Boot Test、Testcontainers（容器化测试） |

## 8. 模型与凭证

- **模型**：使用 **qwen-max**（通义千问 / 阿里云百炼）作为模拟的"AI 服务接口"。
- **API Key**：由面试方提供；也可自选其他模型，但其他模型的 Key 需自行接入。
- **凭证处理**：Key 属敏感信息，**不写入代码与仓库**，本地运行时放入环境变量或 `.env`（并加入 `.gitignore`）。
- **文档**：<https://bailian.console.aliyun.com/cn-beijing/?tab=api#/api/?type=model&url=3016807>

## 9. 时间约束

- **2 天内完成**。

## 10. 评估维度

- 项目结构、代码规范、异常处理、是否有 Bug、架构清晰度。
- "不关心过程，只看最终成果演示"；下一轮面试围绕这份作业展开讨论。
